## 与原版 backend-agent-project-selector 的规则映射

| 研发版规则 | 产品版对应 | 差异 |
| --- | --- | --- |
| 业务型 Agent 强门槛（6 项命中 2-3） | 三层判定 + Agent 四件套 + 产品完整度门槛 | 先分平台/框架/应用，再查 Agent 能力，再查产品形态 |
| 源码证据点 ≥5（Controller/Service/…） | 产品证据点 ≥5（用户/场景/主流程/权限/数据/部署/issues） | 证据类型从代码换成产品素材 |
| 技术难点挖掘（缓存/MQ/一致性/…） | 包装方向设计（垂直化/场景化/指标闭环/迭代） | 输出从工程深度换成产品深度 |
| 简历条目：负责功能 + 技术机制 | 简历条目：责任层级四段结构 + 指标闭环 | 写法侧重完全不同 |
| 分桶：后端技术分桶 + Agent 分桶 | 分桶：通用场景 Agent 分桶 + B 端场景 Agent 分桶 | 按 PM 包装对象重划，全部为 Agent 产品 |
| 模式：agent/backend/mixed/safe/challenge | 模式：ai-product/b2b/mixed/safe/vertical | 全部模式只找 AI Agent 产品；b2b-only 重定义为 B 端场景 Agent；challenge 换成 vertical（行业化是 PM 的差异化杠杆） |
| pull_github_repos.py / markdown_to_pdf.py | 原样复用 | 无改动 |
