# 简历写法（PM 产品版）

写简历条目和面试问答前加载本文件。

## 核心原则

1. **责任层级优先**：每条经历必须体现「需求洞察 → 方案设计 → 推动落地 → 指标闭环」的完整责任链，禁止"参与了 / 协助了 / 了解了"这类自我降权表述。
2. **0-1 叙事边界**：项目可按 0-1 项目叙事，但前提是吃透架构与选型；简历中不得把"建议改造"写成"已完成成果"，除非用户确认已完成。
3. **垂直落地压过通用 Demo**：叙事落点是"垂直行业 AI 落地"，不是"我做了一个 Agent"。行业认知（数据口径、业务流程、合规边界）是差异化卖点。
4. **每条可追问**：简历上每个数字、每个设计决策，都必须能往下追问两层而不露馅。

## 简历条目结构（每条四段）

```text
[场景与问题] 在 X 业务场景下，存在 Y 问题（用数据/现象说明）
[方案与职责] 我主导/独立完成 Z 方案设计（明确责任边界：PRD、数据定义、评测集、推进动作）
[关键机制]   其中 1-2 个有深度的设计决策（为什么这样选、放弃了什么）
[结果与指标] 用指标闭环收口（已有真实数据则写实数；未上线则写"目标指标 + 验证方式"）
```

## 写法示例（通用示例，行业随用户实际经历替换）

**较弱写法（禁止）：**
> 参与开源项目的研究，了解了 RAG 和 Agent 技术。

**合格写法：**
> 针对电商客服团队「咨询量大、重复问题占比高」的问题，独立完成智能客服助手 0-1 方案：基于开源项目二次开发，完成产品定位、功能架构（知识问答 / 话术推荐 / 工单摘要）、知识库数据治理方案（FAQ 与历史会话清洗切分规则）与评测集设计（50 条真实咨询基线）；定义北极星指标为「自助解决率 ≥60%」，过程指标覆盖召回命中率、答案引用覆盖率、转人工率。

（同款结构可替换为教育、金融、医疗、制造等任意行业的场景，骨架不变：场景问题 → 方案与责任边界 → 关键机制 → 指标闭环。）

## 面试问答准备（每个项目必备 7 组）

1. **选型层**：为什么选这个开源项目做底盘？对比过哪些替代方案？（至少能说出 2 个替代品和取舍理由）
2. **架构层**：RAG / Agent / 记忆 / 工具调用的基本原理，能画出项目架构图。
3. **数据层**：知识库数据从哪来、怎么清洗切分、质量怎么保障；坏数据怎么发现和修复。
4. **评测层**：怎么证明它好用？评测集怎么建、指标怎么定、badcase 怎么迭代。
5. **边界层**：哪些场景它解决不了？什么时候转人工 / 拒答？工具返回空数据、超时、高风险动作的兜底方案是什么。
6. **成本层**：单次调用成本、P95 延迟、模型路由策略；能回答"成功率提升 2% 但成本涨 3 倍，发不发"。
7. **迭代层**：如果再给你一个月，优先做什么？为什么？（考察优先级判断）

## 三层标准 → 简历与问答的落点

| 面试层级 | 简历 / 问答的落点 | 判据 |
| --- | --- | --- |
| 硬门槛 | 现场可跑 demo、能画架构图、四件套点名（多轮 / RAG / 工具 / 记忆） | 缺一项即被刷 |
| 分水岭 | 评测集（样本来源、成功判定、跑几次）、一个 badcase 七步归因、兜底清单、成本与延迟数字、记忆分层、人机边界 | 决定 15k 还是 25k+ |
| 加分项 | 行业规则与口径、数据治理、POC→试点→验收、Trace 可观测、合规权限、商业价值 ROI | 决定是否被记住 |

一条原则：**对话形态是入场券，不是竞争力。** 十份简历八份写"多轮 + RAG + 记忆 + 工具调用"，真正的区分度在第二层——面对模型不确定性时，你设计过什么产品化的管理机制。

## 禁止事项

- 禁止把开源项目原名直接写上简历后不加任何自己的改造（会暴露"只是部署了一下"）。
- 禁止编造未发生的用户量、上线事实；未上线项目用"试运行 / 小范围真实用户"表述并如实准备口径。
- 禁止只有功能清单没有指标；禁止只有指标没有机制。
- 禁止跨行业乱贴：叙事必须收敛到用户真实经历能支撑的一条垂直线，同一份简历不得出现两个互不相干的行业故事。
