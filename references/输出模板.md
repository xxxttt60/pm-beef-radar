# 输出模板（PM 产品版）

生成 `pm-project-resume-pack.md` 前加载本文件。

```markdown
# PM 项目推荐报告

> 生成时间 / 推荐模式 / 用户画像摘要（目标岗位、垂直行业、体验能力、时间预算）

## 一、候选池概览

| 项目 | 链接 | 分桶 | 语言 | Star | 初筛分 | 一句话定位 |
（列出候选池中未淘汰项目，标注分桶多样性说明）

## 二、最终推荐（2-3 个）

### 项目 N：{产品命名}（{owner/repo}）

- **链接**：{url}
- **Star / 语言 / 最近更新**：
- **分桶**：
- **产品形态**：自带 UI / 嵌入平台机器人 / API 服务 + 交互文档 / CLI（注明演示方式与演示成本）
- **产品定位（命名建议）**：把候选项目重命名为一个业务产品，如"面向{用户行业}的智能问数助手"（行业随用户输入变化）
- **Agent 四件套打勾**（有 / 无 / 待验证 + 证据位置）：
  - 多轮上下文：…
  - RAG 检索：…
  - 工具调用：…
  - 记忆：…
- **目标用户与核心场景**：
- **已有能力**（来自本地仓库验证，标注证据来源）：
  1. …（功能模块、角色权限、数据对象、部署方式等）
- **建议改造 / 0-1 路线**（明确标注"完成改造后可写入简历"）：
  1. 垂直化：…
  2. 场景化：…
  3. 指标闭环：北极星指标 + 过程指标
- **简历条目**（按 简历写法.md 四段结构）
- **面试追问预案**（7 组问答要点）
- **体验成本评估**：部署方式、依赖、预计跑通时间（safe-mode 必须给 7 天计划）

## 三、产品验证摘要

| 项目 | 拉取状态 | 阅读的关键文档/目录/配置 | 产品证据点（≥5） | issues 痛点素材 |

## 四、面试三层对照表

| 层级 | 要求项 | 现状 | 改造动作 | 优先级 |
| --- | --- | --- | --- | --- |
| 硬门槛 | 能现场跑通主流程 | | | P0 |
| 硬门槛 | 多轮上下文 / RAG / 工具调用 / 边界认知 | | | P0 |
| 分水岭 | 评测集（样本来源、成功判定、跑几次） | | | P0 |
| 分水岭 | badcase 七步归因 | | | P1 |
| 分水岭 | 不确定性兜底（空数据/超时/高风险/转人工） | | | P0 |
| 分水岭 | 成本与延迟（单次成本、P95、模型路由） | | | P1 |
| 分水岭 | 记忆分层（强记忆 / 弱衰减 / 纠错过期） | | | P1 |
| 分水岭 | 人机边界（哪些必须人工确认） | | | P1 |
| 加分项 | 行业 know-how / 数据治理 / 合规权限 / 商业价值 | | | P2 |

## 五、淘汰与降权说明

| 项目 | 理由 |

## 六、可替换项目

（每个推荐项目给 1 个同分桶替补，说明差异）

## 七、下一步行动清单

（跑通步骤 / 改造顺序 / 简历改写动作，按周拆解）
```

要求：

- 每个推荐项目必须先过产品验证摘要表，缺证据点不得出现推荐章节。
- "已有能力"与"建议改造"用不同标记区分，防止误写为已完成。
- 证据来源写具体：文件路径 / 目录名 / issue 链接。
